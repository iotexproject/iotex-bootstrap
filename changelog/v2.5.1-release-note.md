# v2.5.1 Release Note

## Summary

v2.5.1 is a maintenance patch on top of v2.5.0. It carries a dependency update and four robustness fixes in block decoding, transaction decoding, p2p message handling, and the block/receipt read path. No hardfork, no genesis change, and no config schema change — v2.5.1 introduces no new activation heights, and the Zanzibar schedule from v2.5.0 is unchanged (MainNet block **53533081**, estimated 2026-10-19 02:00 UTC).

v2.5.1 also restores the prebuilt binaries on the GitHub release page. The v2.5.0 release was published without them because the release build failed; v2.5.1 ships `iotex-core` and `ioctl` binaries with `.asc` signatures as before.

The macOS assets are renamed from `*-darwin-amd64` to `*-darwin-arm64`. Since v1.14.1 those files have been Apple Silicon (arm64) builds published under an Intel name; the contents are unchanged, only the name now matches. Scripts that download `iotex-core-darwin-amd64` or `ioctl-darwin-amd64` should switch to the `-darwin-arm64` names. There is no Intel macOS build.

## Changes

### Fix

- **block: return an error for block protos without a body** — a block proto with no body is now rejected during decoding instead of being dereferenced.
- **action: validate signature R/S length for eth-encoded txs** — signature values longer than 32 bytes are rejected when decoding a transaction.
- **p2p: validate consensus topic messages and do not block broadcast delivery** — the consensus topic only accepts consensus messages, and actions over the per-sender rate are dropped instead of stalling message delivery.
- **blockchain: stop mutating shared cached blocks and receipts on read paths** — attaching blob sidecars and patching transaction logs now operate on copies, so concurrent API and block-sync readers no longer touch the same cached objects.

### Dependency

- **deps: update go-pkgs to v0.1.16** (#5028)

## Upgrade Priority

v2.5.1 is **recommended** for all node types. Nodes already on v2.5.0 are ready for Zanzibar; nodes still on v2.4.x must upgrade before MainNet block 53533081 and should go straight to v2.5.1.

| Node type     | Action            |
| ------------- | ----------------- |
| Delegate      | **Recommended**   |
| Fullnode      | **Recommended**   |
| API node      | **Recommended**   |
| Archive node  | **Recommended**   |

No genesis or config schema changes are required. No database migration, resync, or snapshot reload is needed — upgrading is a straight image swap from v2.5.0. The `txlog.db.patch` is unchanged from v2.5.0; see the [v2.5.0 release note](v2.5.0-release-note.md) for it and for the full Zanzibar details.
