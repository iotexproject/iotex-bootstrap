# v2.5.2 Release Note

## Summary

v2.5.2 is a maintenance release on top of v2.5.1. It hardens the API, p2p, block sync, the action pool, minting and consensus, and carries a set of correctness fixes across the node. **No hardfork**: there is no new activation height, no genesis change, and no config schema change, and MainNet history replays to identical state. The Zanzibar schedule from v2.5.0 is unchanged.

Some defaults and limits change, mainly in the API and in consensus. Read [Changes operators will notice](#changes-operators-will-notice) before upgrading, especially if you run a delegate or a public API node.

## Changes operators will notice

### Delegates: round lock and signing records

- `consensus.rollDPoS.enforceRoundLock` is **on by default**. A delegate signs only for the block it is locked on in a height, unless it is shown a proof of lock from a later round. The lock and the last signed votes are kept in the consensus DB. Setting it to `false` restores the previous behaviour.
- **`consensusDBPath` must be on persistent storage.** The default from this repo, `/var/data/consensus.db`, already is: it is under the `$IOTEX_HOME/data` volume in the docker commands below.
- **Do not restore `consensus.db` from a backup or snapshot, and do not copy it between nodes.** An old copy still holds signing records, so the node treats its signing state as intact, skips the sit-out below, and may sign again at the next height. If the file is damaged, delete it; the node then starts without signing state.
- A delegate that starts without readable signing state sits out its first rounds at the next height, unless the other delegates cannot form a quorum without it. **This happens once on the first start after upgrading from v2.5.1 or earlier**, because older versions did not write signing records. It is expected and lasts at most one height. Upgrade delegates in turn rather than all at once.
- Nodes that are not delegates also log `signed votes from before this start are unknown` at startup. They never sign, so the warning is harmless there.

### Block sync

- `dispatcher.blockSyncRequestBurst` (default 30) and `dispatcher.blockSyncRequestRefillPerSecond` (default 5) throttle block sync requests per peer with a token bucket. They replace the fixed sync request interval; `dispatcher.processSyncRequestInterval` is deprecated and ignored.
- Block sync bans a peer only for an error the served block itself causes. Local failures no longer ban honest peers.

### API

- The `debug_trace*` methods accept **native tracers only**; JavaScript tracers are no longer supported. The trace timeout still defaults to 5s, and a caller-supplied timeout is capped at 30s. Struct-log output defaults to 16 MiB, with a 64 MiB maximum, and at most 8 traces run at once.
- A websocket connection holds at most **32 subscriptions**, and its message rate limit applies per connection.
- The JSON-RPC HTTP request body is limited to **15 MiB**.
- `eth_subscribe` inside a batch request returns an error. A single `eth_subscribe` is unchanged.
- `eth_newFilter` and `eth_newBlockFilter` return random filter IDs. The `0x` + 64 hex format is unchanged.
- `latest` and `eth_blockNumber` follow receipt availability, so they can trail the chain tip by a few seconds while receipts are indexed.
- `eth_getLogs` supports the `blockHash` filter, and reads `fromBlock: 0x0` as the first block.

### Action pool

- When the pool is full and the incoming action is itself the one evicted, the submission now fails with `ErrTxPoolOverflow` instead of reporting success.
- Non-executable actions are evicted before executable ones.

### Monitoring

- The inbound block watchdog no longer restarts the node. It logs and exports `iotex_chainservice_stalled_tip_ticks`. Alert on this metric if you relied on the restart.
- New metric `iotex_mint_skipped_actions_total` counts actions left out of a block during minting.
- The per-peer label is removed from `iotex_p2p_message_counter`. Dashboards that group by it need updating.

### IOSwarm

- `ioswarm.masterSecret` is required when IOSwarm is enabled.

## Changes

### Hardening

- **action / actpool**: tx container decoding and validation, bundle size limits, out-of-range candidate endorsement ops, eviction order when the pool is full, and the per-account blob cap.
- **minting (state/factory)**: an action that fails is left out of the draft instead of the whole draft being dropped; nonces are checked against the start of the block; bundles keep their own block context; candidate actions are deferred after an owner or operator change.
- **p2p / dispatcher / blocksync / actsync**: per-peer and per-message bounds, the authenticated peer identity for relayed broadcasts, bounded block buffers and sync request ranges, and token-bucket throttling of sync requests.
- **api**: tracing limits, websocket subscription bounds, and the request body limit.
- **consensus**: the round lock, persisted signed votes, and startup without signing state.
- **ioswarm**: work accounting, scheduling and settlement.
- **metrics**: bounded label values for p2p message and node info metrics.

### Fix

- **consensus**: skip a height that `CommitBlock` reports as already committed (#5014).
- **blockindex**: revert pending changes when indexing a block fails (#5027).
- **filedao**: refuse writes after a failed batch write until reopened (#5035).
- **chainservice**: propagate the block store construction error (#5016).
- **genesis**: read the SetCode authority blacklist from genesis per chain; the MainNet list is fixed in code, and `actPool.blackList` in node config now applies to admission only (#5041).
- **actpool**: report overflow when the newcomer itself is evicted, re-check the blob cap on the worker (#5042), and take the write lock in `Reset` and `PendingActions` (#5033).
- **action**: include the blob fee in a tx container's cost (#5036).
- **factory**: copy the write queue only when a state diff callback is set (#5043); do not treat history as pruned before the tip passes the retention (#5038).
- **state, action, db**: eight small correctness fixes (#5048).
- **api**: serve a tx receipt as soon as its block is queryable (#4913); filter IDs, batch subscribe and trace fixes (#5044); support `blockHash` in `eth_getLogs` (#5039); key the contract read cache on the caller and the whole call (#5034); return errors instead of panicking on malformed web3 requests (#5037).
- **rewarding**: serve `pendingVoterRewardDelegates` on archive readers (#5000).
- **gasstation**: scale fee history reward percentiles to 0-100 (#5032).
- **messagebatcher**: options no longer mutate the default writer config (#4961).

### Dependency and CI

- **deps**: google.golang.org/grpc 1.83.2 (#5015), go.opentelemetry.io/otel/sdk 1.45.0 (#5019).
- **ci**: run tests in parallel and cache Go builds (#5062); gosec 2.30.0 (#5002, #5064); stop the e2e test server when a test ends (#5061).
- **docs**: expand the security policy (#5060).

## Testing

MainNet history from 28,000,000 to 54,000,000 was replayed with these changes, with every block's state digest matching, including the blocks after the Zanzibar activation. The release tree then replayed 52,000,000 to 54,598,070, again with every digest matching.

## Upgrade Priority

v2.5.2 is **recommended** for all node types.

| Node type     | Action            |
| ------------- | ----------------- |
| Delegate      | **Recommended**   |
| Fullnode      | **Recommended**   |
| API node      | **Recommended**   |
| Archive node  | **Recommended**   |

No genesis or config changes are required. No database migration, resync or snapshot reload is needed: upgrading is a straight image swap from v2.5.1 or v2.5.0. Delegates: see [Delegates: round lock and signing records](#delegates-round-lock-and-signing-records) before you restart. The `txlog.db.patch` is unchanged from v2.5.0.
